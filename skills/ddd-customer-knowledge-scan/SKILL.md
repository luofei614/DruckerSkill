# 企业顾客与知识现状感知扫描

## 一句话定位

对话式问卷工具：用户说"开始企业顾客和知识现状感知扫描"，AI 分组推送 11 道选择题 + 2 道开放题，用户点选/自由作答，AI 归一化为标准选项后，通过 `submit.py` 一次性提交到秒哒大屏后端。主持人在大屏页面实时看汇总。（已移除"场次"概念，每次扫描前由维护者清空后端历史数据。）

## 前置条件

- 本机已安装 Python 3（标准库即可，零第三方依赖）
- `scripts/submit.py` 中 `API_URL` 已回填线上地址，开箱即用（无需任何配置）
- 后端 API 已上线可用（秒哒 Supabase Edge Function，已实测）
- **主持人大屏地址**：`https://3f4685b5256243dda9641ad29c8adc73.app.codebuddy.work`（手写 HTML 大屏，读同一 GET API，每 5 秒刷新，含 11 张占比条形图 + 开放题逐条答案罗列（关键词加粗）；秒哒自带前端因发布失败暂不使用）

## 答题交互方式（必须遵守）

**所有选择题必须用 WorkBuddy 内置的「向用户提问」选择组件（AskUserQuestion 工具）推送，不得用纯文本罗列题目。**

- **字段用法（已查证工具 schema，务必遵守）**：
  - `question` 字段**无长度上限**，是弹窗主文本区——**完整题干必须放在这里**，可完整、清晰展示，不再缩写。
  - `header` 字段**硬性 `maxLength: 12`**，渲染为顶部小标签/胶囊，**只放 ≤12 字分类标签**（如 "R1 视角"），严禁把题干塞进 `header`（否则会显示过短、周围大量空白）。
  - `options[].label` 写**选项原文**（如"部分符合"，直接作为提交值，不做二次转换）；`description` 写极短提示（如"选最贴近的一项"），不得为空。
- **单次调用题量 ≤ 3 题**：历史上「4 题 + 长题干」曾导致弹窗渲染空白；改用 `question` 承载完整题干后，单次 3 题以内最稳。
- 用户点选后即得标准答案，**无需口语归一化**；仅当用户在"其他"输入自由文本时，才按「LLM 归一化规则」处理。
- **Q1/Q2 开放题严禁用选择组件** —— 必须用普通对话（自由文本）提问，让用户直接输入作答。选择组件拿不到自由文本、只返回预设选项，会让开放题收不到真实答案（本次实测踩坑：选了选项却拿不到文字，已改回普通对话提问）。
- 纯文本罗列题目仅作为选择组件不可用时的降级方案（降级时按归一化规则处理口语作答）。

## 答题流程（约 6 轮对话）

### 第 1 组：顾客视角（R1–R3，3 题）

用选择组件一次推送 3 道题，`question` 放完整题干，`header` 放题号+短标签（如 "R1 视角"），`description` 写"选最贴近的一项"：

```
R1. 企业内部人往往没有顾客视角，大部分人不真正懂顾客。这符合咱们企业的情况吗？
    ①符合  ②部分符合  ③完全符合

R2. 我们清楚顾客在用我们的产品/服务时，真正获得的满足感是什么吗？
    ①不清楚  ②部分清楚  ③完全清楚

R3. 我们能按"顾客看重的满足感"把真正的竞争对手分清楚吗？
    ①不清楚  ②部分清楚  ③很清楚
```

用户点选后答案即为选项原文，内部记录，不发回用户（隐私），直接进入下一组。

### 第 2 组：顾客视角（R4–R6，3 题）

同样用选择组件一次推送 3 道题：

```
R4. 我们的精力常花在自己看重的质量上，却没检查过顾客是否真在意。这符合咱们的情况吗？
    ①不符合  ②部分符合  ③完全符合

R5. 我们的产品并不是顾客"离不了"的。我们意识到这一点了吗？
    ①没意识到  ②部分意识到  ③完全意识到

R6. 企业在"主动去找顾客、研究顾客"这件事上下了多少功夫？
    ①不重视  ②偶尔重视  ③十分重视
```

### 第 3 组：顾客行为 + 知识（R7–R8, K1，3 题）

同样用选择组件一次推送 3 道题：

```
R7. 我们清楚"真正做购买决定的人"是谁吗？
    ①不清楚  ②部分清楚  ③很清楚

R8. 我们做到"以市场/顾客的最终用途为起点"来思考业务了吗？
    ①没有做到  ②偶尔做到  ③做得很好

K1. 我们独有的本事，往往是"看似简单、其实最难被复制"的。我们意识到这点了吗？
    ①没意识到  ②部分意识到  ③完全意识到
```

### 第 4 组：知识本事（K2, K4，2 题）

同样用选择组件一次推送 2 道题：

```
K2. 我们的独门本事，是否在持续更新、刻意练习（例如每半年一次）？
    ①没更新  ②偶尔更新  ③持续更新

K4. 我们分得清"难复制的知识"和"花钱就能买到的资源"吗？
    ①不清楚  ②部分清楚  ③很清楚
```

### 第 5 轮：开放题 Q1

```
【开放题 1/2】
Q1. 我们有哪些盲区——有哪些重要的事情，其实一直被我们忽略了？
（请自由作答，至少一句话）
```

### 第 6 轮：开放题 Q2

```
【开放题 2/2】
Q2. 我们有哪些能力——自己觉得很简单、没被重视，但行业里其他人其实很难做到的？
（请自由作答，至少一句话）
```

### 提交

所有题目答完后，AI 组装 JSON 并调用 `submit.py`：

```bash
python3 <skill_dir>/scripts/submit.py '<json>'
```

JSON 结构（submit.py 自动附加 token，不再传 session 字段）：
```json
{
  "choices": {"R1":"部分符合","R2":"部分清楚","R3":"部分清楚","R4":"部分符合","R5":"完全意识到","R6":"偶尔重视","R7":"很清楚","R8":"偶尔做到","K1":"部分意识到","K2":"偶尔更新","K4":"部分清楚"},
  "open": {"Q1":"用户原文","Q2":"用户原文"}
}
```

提交成功 → AI 回复"答题完成，感谢参与！请查看工作坊现场屏幕上的实时汇总结果。"
提交失败 → `submit.py` 自动暂存到本地，AI 提示"网络异常，答卷已暂存，稍后会自动重发。"

**提示文案约束**：AI 在提交成功后的回复**只引导用户去看工作坊现场屏幕**，严禁在回复中输出任何大屏/实时看板的网址链接（如 appmiaoda、codebuddy、CloudStudio 等地址）。网址仅存在于本文件维护者须知中，面向参与者一律不展示。

## LLM 归一化规则

仅在两种情况下使用：① 用户在选择组件的"其他"里输入了自由文本；② 组件不可用降级为纯文本答题。此时 AI 按以下规则归一化为**选项原文**（非 A/B/C）：

| 用户可能说法 | 归一化为 |
|---|---|
| "符合""是的""就是这样" | 符合 |
| "部分符合""差不多""基本符合" | 部分符合 |
| "完全符合""完全是这样""非常符合" | 完全符合 |
| "不理解""不清楚""不知道" → 但需区分题意 | 按题意匹配最接近的选项 |
| "不太清楚""一般""部分清楚" | 部分清楚 / 不清楚（按题意） |
| 数字"1""2""3" | 对应①②③ |
| "A""B""C" | 对应①②③ |

**原则**：拿不准时优先匹配语义最接近的选项；实在无法判断时，AI 主动追问该题，不猜。
**选项顺序**：所有题目的选项均按认知/符合度**由低到高**排列（①最低 ③最高），归一化时保持此语义。

## 红线（不做的事）

- ❌ **不做德鲁克解读/洞察/建议** —— 本 Skill 只收与传，分析交给 `ddd-customer-insight` 等后续环节
- ❌ **不擅自改题面、不增减题目** —— 题库固定在 `references/survey_config.yaml`，单一事实源
- ❌ **不把用户答案原文发回给用户** —— 归一化结果内部记录，保护隐私
- ❌ **开放题（Q1/Q2）禁用选择组件** —— 必须用普通对话自由文本提问；选择题才用 AskUserQuestion 选择组件，二者不可混用
- ❌ **不虚构罗列数据** —— 开放题答案与加粗关键词均基于真实提交，由大屏前端计算生成

### 清空数据（每次重新扫描前必须执行）

本工具不区分场次：答卷统一进入同一张表，提交时不再传 `session` 字段（后端已去除该判断）。因此**每次开始新一轮扫描前，必须先清空后端历史数据**，否则新旧答案会混在一起。

1. **本地临时暂存**：删除 `~/.customer_knowledge_scan_pending/` 目录下所有 `*.json`（失败重发残留）。
   ```bash
   rm -f ~/.customer_knowledge_scan_pending/*.json
   ```
2. **后端真实数据**：登录秒哒 → 进入该应用编辑页 → 「数据 / 数据库」→ 找到答卷表（api-answers 对应的数据表）→ 清空/删除全部行；或在 Supabase 控制台对该表执行 `DELETE FROM <答卷表>`。
   > ⚠️ 具体表名与后台菜单以实际秒哒/Supabase 后台为准；若路径有变，请在此处同步更新。
3. 清空后刷新大屏，确认「已收答卷」归零，再开始新扫描。
