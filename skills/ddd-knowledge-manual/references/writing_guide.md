# 知识手册编写指导（德鲁克框架内化）

> 把德鲁克知识观直接内化为手册编写标准。本文件是企业起草/维护知识手册的方法论，配合 `assets/manual_template.md` 使用。

## 一、手册六段骨架（每个 topic 一套）

```
0. 元信息（版本/时间戳/owner/来源/成果锚定）
1. 独特知识清单   —— 每条必须是「动词+名词」(kp-07-08)
2. 资源 vs 知识甄别表 —— 逐条标 R/K，禁把渠道/厂房当知识 (kp-07-02/03)
3. 四维度成熟度   —— 对/值/深/新 自评 (kp-07-07)
4. 知识短板       —— 反向缺口：别人干得了我们干不了 (对称非顾客)
5. 五维机会草稿   —— 事业新机会假设卡 (kp-07-09)
6. 更新日志       —— 历次 diff 摘要 (本 skill 自动维护)
```

## 二、条目锚点规范（kid）

- 每个知识条目用稳定锚点：`## [K001] 在 B站知识区，能持续产出霸榜的高质量视频课`。
- `K001` 是 stable key，**跨版本不变**——这是语义 diff（增/删/改）的前提。
- 改名只改标题文字，不改 kid；删除条目保留 kid 缺口（diff 记为「删除」）。

## 三、动词+名词规范（kp-07-08）
- 格式：「在 **XX 领域**，能做好 **XX 事**」。
- 错误示例：「我们质量好」「服务卓越」「技术领先」→ 退回改写。
- 检验：删掉所有形容词后，是否还剩一个可观测、可验证的「动作+对象」？

## 四、资源 vs 知识甄别（kp-07-02/07-03）
- **资源 R**：渠道关系、厂房设备、资金、政策红利、品牌流量——可购买/可替代，不计入知识。
- **知识 K**：某人/某团队把信息做成成果的能力，难复制。
- 甄别表逐条打 R/K；手册「独特知识清单」只收 K。

## 五、四维度成熟度自评（kp-07-07）
| 维度 | 自评问题 | 薄弱信号 |
|---|---|---|
| 对(正确) | 指向领先？有顾客证据？ | 无外部验证 |
| 值(回报) | 收入真来自这？还是渠道？ | 收入靠资源拉动 |
| 深(融入) | 系统化嵌入交付？还是只在几人脑中？ | 关键人风险 |
| 新(改进) | 过时风险？哪些场景浪费？ | 从不更新 |

## 六、易腐分级（kp-07-06）
- 每条知识标 `perishability`：
  - **高**：技术/潮流敏感（如平台算法、营销玩法）→ 审查周期 **90 天**
  - **中**：方法论/流程 → **182 天（半年）**
  - **低**：底层原理/长期资产 → 可 >182 天，但仍需回顾
- `next_review_due` 由 `perishability` 推导（见 SKILL.md ②）。

## 七、知识短板（反向缺口）
- 对称顾客侧的「非顾客」：列出「别人干得了、我们干不了」之处。
- 用途：反向喂回 `ddd-knowledge-survey`/`insight` 做下一轮探询补全。

## 八、五维机会草稿（kp-07-09）
- 顾客三问 × 独特知识 × 企业渴望 × 外界变化 × 未满足需求 → 事业新机会假设卡。
- 一律标「草稿·假设·待验证」，不展开完整知识库。

## 九、Word 交付物（必须同步产出）
- 每次生成/更新手册，必须同时产出 **Word(.docx)** 交付物：用 `scripts/export_docx.py` 把手册 markdown **真实转换**（标题/引用/表格/列表/加粗），**禁止仅改文件后缀**。
- 面向客户、打印、归档场景优先给 .docx；平台同步（飞书/钉钉/企微）是另一类视图，不替代 Word。
- Word 与源 markdown **同名同目录**（仅后缀不同），便于追溯与版本对齐。

## 十、文件命名与 topic 规范（强制）

- **文件名用中文业务名**，格式：`{中文业务名}_v{n}.md` / `.docx`。
  - ✅ 正确：`王德峰视频课业务知识手册_v1.md` / `王德峰视频课业务知识手册_v1.docx`
  - ❌ 错误：`wangdefeng-video-course-v1.md`（英文/pinyin slug 不可作文件名）
- **topic 是内部稳定 id**（跨版本不变，用于 VERSION_INDEX 查找与语义 diff 锚定），建议用中文业务名（如 `王德峰视频课业务`），与文件名解耦——文件名可含「知识手册」等后缀，topic 不必含。
- `stamp_version.py` 现已改为**记录真实文件路径**（`os.path.relpath(真实--file, repo)`），不再用 topic 拼文件名；因此文件名由起草时决定（中文），脚本只负责登记，不会对不上。
- 改名后务必同步更新：① 文件本身、② `VERSION_INDEX.json` 的 `file` 与 `topic`、③ 手册 frontmatter 的 `topic`，三者 topic 一致。
