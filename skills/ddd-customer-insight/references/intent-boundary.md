# 能力边界详解 · 输入参数 · 平台检测补充（分析视角）

> 本文件承载 `SKILL.md` 下放的细节层（资源边界原则：SKILL.md 只留路由/骨架/契约/红线，细节在此）。本技能做的是「分析」，承接 `ddd-customer-survey` 的上游产出。

## 一、能力句（Capability Sentence）

> 把德鲁克的顾客分析框架，固化为「输入调研结果（原话/整合表）→ 输出顾客现实画像 + 非顾客机会 + 价值锚点 + 看懂顾客两问 + 竞争空白 + 画布/报告」的可复用能力，使每次分析都自动带非顾客视角、原话溯源与置信度，且客户产物纯净可用。

## 二、近邻排除项（Exclusions，详解）

| 排除项 | 说明 | 交由谁 |
|---|---|---|
| ASR 录音转写 | 只吃文本结果，不转音频 | C2 转写环节 |
| 重新设计问卷/提纲 | 只分析已有结果 | `ddd-customer-survey` |
| 知识诊断 / 独特知识提炼 | 本技能不含知识分析画布，D1 仅轻量列出候选 | 思路③ 知识坊侧 |
| 替企业下结论 / 出战略建议 | AI 只提取·组织·升维，决策归人 | 企业决策者（人工复核） |
| 数据采集与统计聚类 | 只消费已有结果，不做抽样/聚类 | 下游数据技能 |
| 营销战略咨询 | 不做战略建议，只做洞察草稿 | 咨询/管理层 |

## 三、完整输入参数表

**必填参数**（缺失须先追问，一次 ≤5 项，按优先级）

| 参数 | 含义 | 示例 |
|---|---|---|
| `raw_results` | 调研结果文本：访谈原话 / 收集表 / 整合表；`ddd-customer-survey` 已结构化的 `analysis_schema`（题→画布字段+原话溯源）最佳 | 「S3 场次 12 段原话 + 整合表」 |
| `business_context` | 事业/产品一句话，用于校准画像与价值锚点 | 「道家线上课：都市白领压力管理」 |
| `output_targets` | 需要哪些产物（默认全产：画布 HTML + 报告 HTML） | 画布 + 报告 |

**建议参数**（缺省由 skill 反推并标注「假设」）

| 参数 | 含义 |
|---|---|
| `assumption_pre` | 企业预填「我们以为」（用于①立场校准对照） |
| `sample_meta` | 样本量、场次、分群，用于置信度判定基准 |
| `include_non_customer` | 是否含非顾客归因（默认 **true**，德鲁克硬约束） |
| `focus` | 侧重输出（画布偏/报告偏/两问草稿偏），默认均衡 |
| `platform_sink` | 是否要沉淀到平台结构化表（默认检测飞书后询问） |

## 四、平台检测与分发说明（配合 ⑦⑧ 步）

- 检测时机：步骤 ⑧ 进行，**不假设**始终可用——读取当下 `<connector-status>` 的 `feishu` / `dingtalk` / `wecom` 的 `connected` 项，并做活体确认（见 `references/collab_delivery.md`）。
- 三平台（飞书多维表格 / 钉钉多维表·钉钉文档 / 企微在线表格·企微文档）能力由矩阵定义，**SKILL.md 不写死平台名**；新增平台只改矩阵 + 加适配器文件。
- 任一工具未连接时不谎称可用；输出纯 HTML/PDF 让用户自行导入或连接后补推（/publish）。
- 红线贯穿：无论落到哪个平台，原话溯源与置信度字段不可省略；客户产物纯净度检查不变；推送层只搬运不改写、不替企业下结论。

## 五、与上游的衔接契约

- 输入若来自 `ddd-customer-survey` 的 `analysis_schema.md`（题—答—原话 mapping），本技能跳过 ① 轻量映射，直接进入 ②③④ 升维。
- 输入若是纯原话（无 schema），本技能先在 ① 做轻量「题/主题 → 画布字段」映射，再升维。
- 输出可向下游 C9 知识库沉淀（顾客现实、非顾客机会、价值锚点作为知识资产候选）。
