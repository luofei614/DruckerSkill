# 德鲁克知识问答（ddd-knowledge-qa）

> 从 `~/DruckerWiki` 知识库检索德鲁克管理思想，基于检索内容回答用户问题。知识库含四书 **339 个知识点（KP）+ 14 个跨书概念合订页**，每个 KP 带「原话观点 / 原书原文摘录 / 关键论点 / 核心定义 / 概念关系 / 企业应用」等标准段。

## 触发场景
1. **解释德鲁克著作内容**：用户请求解释某书、某章、某概念（如「解释《管理的实践》第6章」「德鲁克怎么讲目标管理」「顾客三问是什么」）。
2. **以德鲁克思想解答问题**：用户提出管理问题，希望用德鲁克的观点思考（如「企业该如何定义自己的事业」「知识型员工怎么管理」「为什么创新不能靠灵感」）。

## 能力边界（4问）
- **做什么**：检索相关 KP/概念页，组织带德鲁克原话引用、核心论点、概念辨析、企业应用视角与出处的回答。
- **不做什么**：不编造库内不存在的德鲁克观点；不做企业诊断/咨询结论（只提供德鲁克视角，不替企业下结论）；不替代 ddd- 家族的调研设计/洞察技能（那些是从零设计调研，本技能是「就库问答」）。
- **何时用**：用户明确指向德鲁克思想/著作，或希望用德鲁克框架思考某管理问题。
- **输入/输出**：输入自然语言问题；输出纯净 Markdown 回答（原话 + 论点 + 辨析 + 应用 + 出处）。

## 检索逻辑（如何找）
1. 解析问题，提取主题词/痛点词/概念词；识别是否含**书名 + 章号**限定（如「《管理的实践》第6章」）。
2. **调用检索脚本精排（推荐）**：
   ```bash
   python3 scripts/retrieve.py "<用户问题>" --top 6
   ```
   脚本做多路召回：概念精确匹配（title/aliases/tags）+ 2-gram 语义重叠 + 同义词扩展（客户→顾客、成效→成果等）+ 书名章号定向，返回 top-N（路径 / 标题 / 出处 / 摘要 / 命中字段 / 片段）。`--json` 可输出机读结构。
3. **手动检索兜底**：若脚本不可用，按 `references/drucker_wiki_guide.md` 地图走：`index.md` 跨书痛点地图 → `concepts/` 概念合订 → 各书 `<书名>.md` 索引 → 遍历 `kp/`。
4. **读取全文**：对 top 结果，读取对应 KP 文件，重点取「原话观点 / 原书原文摘录」「关键论点（德鲁克原意）」「核心定义」「概念关系」「企业应用」「自检·引导问题」。
5. **coverage 诚实**：命中 `coverage:🔴`（库内外部依赖）的框架，主动提示「此框架库内为外部依赖，需另查《书名》第X章」。
6. **跨书串联**：经 KP 的 `## See Also` 与 `see_also_external` 补充相关知识点，形成完整图景。

> 检索算法细节（字段权重、同义词、书序、输出格式）见 `references/retrieval_algorithm.md`。

## 答案生成逻辑（如何答）
1. **立场校准**：以「德鲁克视角」作答，明确这是德鲁克的主张而非普适真理；不替企业下结论（human-in-the-loop）。
2. **直接回应**：1–2 句先给结论。
3. **原话引用**：逐字引用德鲁克原话，标注《书名》第X章（行号来自 KP「原书原文摘录」）。
4. **核心论点**：用「关键论点」「核心定义」「概念关系」展开德鲁克原意。
5. **概念辨析**：澄清与近似概念的边界、常见误区（正面说「该怎样」）。
6. **企业应用视角**：用「企业应用」「自检·引导问题」补充实操，以提问引导用户自省。
7. **AI 补充标注**：当代语境说明明确标「（非德鲁克原意）」，与原文视觉分离。
8. **出处与延伸**：列来源 KP + 相关概念页；命中 🔴 提示另查。

> 回答骨架见 `assets/answer_template.md`；生成方法论见 `references/answer_playbook.md`。

## 输出契约
- 回答为纯净 Markdown，可直接阅读；引用原话逐字并标出处。
- 来源标注到具体 KP（书名·第X章）。
- 库内无对应观点时，明确说「德鲁克未直接论及」，不编造。

## 红线
1. **不编造**：所有论点须可追溯到 KP 的「原书原文摘录」或「关键论点」；库内无则明说。
2. **原话逐字**：引用的德鲁克原话不得改写、不得意译冒充原文。
3. **AI 补充标注**：当代注解须标「（非德鲁克原意）」。
4. **coverage 诚实**：命中 🔴 必须提示外部依赖，不得暗示库内全覆盖。
5. **human-in-the-loop**：提供德鲁克视角与提问，不替代企业做决策结论。
6. **跨书规范**：跨书引用用 `see_also_external` 指向的《书名》#第X章，不靠 id 跨书。

## 门禁（生产级）
- 回答前确认已实际检索到相关 KP（非空结果）；检索为空时如实告知并建议换用德鲁克原书术语。
- 每条原话须能指回具体 KP 与章节；无法指回的「原话」不得出现。
- 不得出现 yao / yao-meta-skill 等生成器标识（本技能为独立交付物）。
