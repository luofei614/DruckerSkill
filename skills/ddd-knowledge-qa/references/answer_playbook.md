# 答案生成方法论（ddd-knowledge-qa）

> 本文件规定如何把检索到的德鲁克知识点，组织为准确、连贯、体现德鲁克核心理念的回答。配合 `assets/answer_template.md` 使用。

## 1. 总体原则
- **由外而内**：德鲁克底层逻辑是「成果在外部、由外部裁定」。回答始终从顾客/市场/成果视角出发，而非内部产能或便利。
- **原话为锚**：以德鲁克逐字原话作为论证基石，AI 只做组织与当代语境说明，绝不冒充原文。
- **human-in-the-loop**：提供德鲁克视角与自省提问，不替企业/用户下决策结论。

## 2. 生成七步
1. **立场校准**：开场点明「德鲁克认为……」，区分于普适建议。
2. **直接回应**：先给 1–2 句结论，满足用户「是什么」。
3. **原话引用**：从 KP「原话观点 / 原书原文摘录」取逐字原话，标注《书名》第X章（行号来自原书原文摘录段）。多条按论证逻辑排。
4. **核心论点**：用「关键论点（德鲁克原意）」「核心定义」展开，每条配原书论据。
5. **概念辨析**：用「核心定义·术语辨析」「常见误区」澄清边界，正面说「该怎样」，避免只否定。
6. **企业应用视角**：用「企业应用」「自检·引导问题」给实操抓手，以提问引导用户自省（不代答）。
7. **AI 补充 + 出处**：必要时加「（非德鲁克原意）」当代注解；末尾列来源 KP 与相关概念页，命中 🔴 提示另查。

## 3. 引用规范（红线）
- 原话**逐字**，不可改写/意译；出处格式「《书名》第X章」。
- AI 补充须与原文**视觉分离**并标「（非德鲁克原意）」。
- 库内无对应观点 → 明说「德鲁克未直接论及」，不编造、不模糊。
- 跨书引用用 `see_also_external` 指向的《书名》#第X章，**不靠 id 跨书**。
- 徐井宏解读仅书A 部分 KP 含（`xu:true`），引用须注明「徐井宏说/讲」。

## 4. 多知识点综合
- 用户问宽泛概念（如「目标管理」）→ 优先用 `concepts/` 跨书合订页，再链回各书 KP。
- 用户问某章 → 按书序综合该章全部命中 KP，呈现德鲁克论述脉络。
- 用户问管理难题 → 召回相关痛点 KP（含 symptoms/红旗信号），用德鲁克框架重述问题，给「自检·引导问题」。

## 5. 置信与诚实
- 优先引用 `status: verified` 的 KP；`draft` 可引用但措辞留有余地。
- `coverage:🟢` 库内全覆盖；`🟡` 部分（原书有雏形）；`🔴` 外部依赖——🔴 必须提示另查，不得暗示全覆盖。
- 检索为空 → 如实告知，建议换用德鲁克原书术语（如「顾客」而非「客户」），或缩小到具体书名章号。

## 6. 输出示例（片段）
> **问**：企业该如何定义自己的事业？
>
> 德鲁克在《管理的实践》中用「事业三问」回答：我们的事业是什么、将是什么、应该是什么——且必须从**顾客与价值**定义，而非产品或技术。
>
> 「企业的目的在外部产生成果；企业内部只有成本核心。」——《为成果而管理》第1章
> 「我们的事业是什么，必须由顾客来回答，由顾客来定义。」——《管理的实践》第6章
>
> 核心论点：①事业定义起点是顾客，不是产品；②须在顺境时反复追问；③「将是什么」前瞻市场变化，「应该是什么」主动重构……
>
> 💡（非德鲁克原意）当代语境下，平台型企业常把「事业」误定义为「App 功能」，德鲁克会要求回到「顾客用我们解决了什么外部问题」。
>
