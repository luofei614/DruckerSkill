# Drucker Knowledge Survey Designer（德鲁克知识分析调研设计）

> 本技能与 `ddd-customer-survey` 完全对称：强化能力边界、输出契约、输出风险画像与门禁自检。范围限定在「设计阶段」——即手册 SOP 的 001（对齐问题清单）+ 002（问题探询提纲生成），**不做诊断与提炼**。

## 能力边界（4 问）

- **承接的重复任务**：把德鲁克知识分析方法论固化为「输入事业/业务 + 知识分析目的 → 输出标准化知识探询设计包」的可复用能力。
- **产出**：知识分析方案（内部）+ A/B/C 类探询提纲 + 知识画布框架 + 诊断 schema + 分工安排；客户产物纯净、内部文档物理分离。
- **不路由的近邻（exclusions）**：
  1. 不做知识诊断与提炼（那是下游 `ddd-knowledge-insight` / C7/C8 环节，本 skill 只产出诊断 schema 空框）；
  2. 不替企业下结论——AI 只做「提取与组织」，结论交人工（红线）；
  3. 不实际执行访谈，只产出探询提纲与原问题；
  4. 不做纯问卷工具排版（飞书/钉钉等仅导出可导入格式）；
  5. 不覆盖顾客分析坊（C 类"问优秀顾客"仅提示与 `ddd-customer-survey` 的 D1 共用，不重做）；
  6. 不替代战略/知识管理咨询。
- **细节在 SKILL.md 之外**：完整输入参数、三源问库、防引导校验、KP 预编译、方法矩阵、平台沉淀见 `references/`。

## 何时使用（When to use）

- 用户要为某业务/事业设计知识分析调研或探询提纲（独特知识盘点 / 知识诊断前置 / 事业新机会知识侧输入）。
- 用户提到「德鲁克知识分析」「知识即企业」「独特知识」「三源验证」「跟别人比/跟自己比/问优秀顾客」「知识探询」。
- 需要把探询表沉淀到飞书多维表格 / 钉钉 AI 表格 / 企业微信 AI 表格。

## 总流程（7 步）

```
① 输入校验 → ② 检索德鲁克 KB（预编译）→ ③ 三问拆解与分群 → ④ 三源探询问生成 → ⑤ 防引导校验 → ⑥ 画布+诊断 schema → ⑦ 组装输出 + 平台沉淀
```

详细参数与分支见 `references/intent-boundary.md`（输入参数）、`references/question_bank.md`（三源问库/防引导）、`references/method_selection.md`（方法）、`references/platform_export.md`（沉淀）。

### ① 输入校验
必填：`business_context` / `research_purpose` / `companies` / `known_resources`。缺失先追问（≤5 项，按优先级）。完整参数表见 `references/intent-boundary.md`。

### ② 检索德鲁克 KB（预编译）
默认离线读 `references/drucker_kb_precompiled.md`（kp-07 系摘要 + 探询话术）。仅当用户明确要求原文且本机存在 `~/DruckerWiki` 时，才读 `工作坊/知识分析工作坊.md` 或对应 KP 全文。

### ③ 三问拆解与分群
把「知识分析三问」（我们能做好什么）拆为 A/B/C 三类，并分群指派探询对象（kp-07-04）：
- **A 类（跟别人比，2 题）** → 探询对象：渠道合作伙伴 / 行业同行视角
- **B 类（跟自己比，1 题）** → 探询对象：企业内部对应团队（基于具体成功/失败项目）
- **C 类（问优秀顾客，1 题）** → 探询对象：优秀顾客（可对接 `ddd-customer-survey` 的 D1 数据，避免重复探询）

### ④ 三源探询问生成
按 `question_bank.md` 的 A/B/C 类模板生成探询题，**使用手册原问题、不改写表达**（kp-07-05 原则2：原话记录）。

### ⑤ 防引导校验
套用 `question_bank.md` 的「防引导校验清单」：资源 vs 知识甄别、动词+名词规范、原话至上提示、禁诱导性。核心：开放式原问题、记录原话、拦截形容词伪知识。

### ⑥ 画布 + 诊断 schema
按 `assets/knowledge_canvas_frame.md` 生成知识分析画布空框（附件3：跟别人比/跟自己比/问优秀顾客 → 结论），每格预留「原话溯源」占位；按 `assets/diagnosis_schema.md` 生成诊断 schema 空框（附件4：诊断1/2/3/4），供下游 `ddd-knowledge-insight` 直接消费。

### ⑦ 组装输出 + 平台沉淀
- 客户产物用 `assets` 模板生成并剥离所有 `[kp-xx]` / 德鲁克 / 方法论痕迹；内部文档加「[内部]」前缀分离。
- 默认生成真实 Word(.docx)；连接表格/问卷平台时按 `platform_export.md` 同步生成表单版。
- 平台沉淀为检查项：检测 connector 状态，询问后沉淀。

## 输出契约（Output Contract）

一次运行交付一个知识探询设计包，物理分离为两类：

- **客户产物（纯净）**：A/B/C 类探询提纲 / 知识画布空框 / 分工安排，零方法论痕迹，可直接发给探询执行人与被探询对象。
- **内部文档（[内部]）**：设计理念（德鲁克映射）+ 产物使用说明 + 知识画布框架 + 诊断 schema / 知识分析方案 / KP 索引。
- **交付格式**：默认真实 .docx；有表格/问卷平台则并发生成表单版。

> 客户产物最常犯的 6 类错误与 reviewer 检查项见 `references/output-risk-profile.md`。

## 德鲁克红线（9 条，不可违背）

1. 三源必含（A 跟别人比 / B 跟自己比 / C 问优秀顾客 默认全生成）— kp-07-04
2. 资源 vs 知识甄别：禁止把渠道/厂房/资金等优势表达为"知识"（产品只是知识的物化载体）— kp-07-02 / kp-07-03
3. 动词+名词规范校验：独特知识须"在 XX 领域，能做好 XX 事"；拦截"我们质量好"等形容词伪知识 — kp-07-08
4. 原话至上：探询问原问题、记录管理者原话，禁二次总结改写 — kp-07-05（原则2）
5. 易腐意识：设计包须提示建立半年回顾 / 知识更新机制 — kp-07-06
6. 跨坊桥梁：C 类"问优秀顾客"提示与 `ddd-customer-survey` 的 D1 共用，不重做 — kp-07-04 ↔ D1
7. 成果锚定：设计包开头强制回填"知识分析要服务的成果/行动" — kp-01-01
8. 客户产物纯净度：零 `[kp-xx]` / 德鲁克 / 方法论 / 防引导痕迹
9. 交付格式：默认真实 .docx，有平台则并发生成表单版

## 门禁（生产级）

- **触发自检**：description 覆盖目标用户说法且不过宽（误触发别的技能）。
- **纯净度自检**：客户产物交付前字符串扫描，命中 `kp-` / `德鲁克` / `方法论` / `画布` / `JTBD` 即返工。
- **资源边界自检**：SKILL.md 只承载路由/骨架/契约/红线；细节均在 `references/` 与 `assets/`，无装饰性空目录。
- **人工复核标注**：含结论性表述须标「需人工复核」，不伪造证据。
