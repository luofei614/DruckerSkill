# 能力边界详解 + 完整输入参数表 + 平台检测补充

## 一、完整输入参数表

| 参数 | 必填 | 说明 | 追问优先级 |
|---|---|---|---|
| `business_context` | ✅ | 事业/业务描述（如"山东兄弟食品包装公司"） | 1 |
| `research_purpose` | ✅ | 本次知识分析要服务的成果/行动（成果锚定） | 1 |
| `companies` | ✅ | 涉及的公司/业务线（食品/包装分列） | 2 |
| `known_resources` | ⚠️ | 已知优势（用于资源vs知识甄别，区分资源与知识） | 3 |
| `cross_workshop_d1` | ⬜ | 是否已有 `ddd-customer-survey` 的 D1 数据可复用 | 4 |
| `inquiry_channels` | ⚠️ | 探询执行渠道（访谈/问卷/飞书文档） | 3 |
| `sample_plan` | ⚠️ | 探询对象配额（渠道伙伴 N / 内部团队 N / 优秀顾客 N） | 2 |
| `review_cadence` | ⬜ | 知识更新机制节奏（默认半年回顾） | 5 |

> 缺失必填项先追问，≤5 项按优先级；选填项可给默认值并标注"待补"。

## 二、近邻 exclusion（不路由）

| 近邻 | 应由谁做 | 本 skill 动作 |
|---|---|---|
| 知识诊断（四维度） | `ddd-knowledge-insight` / C7 | 只产出诊断 schema 空框，不诊断 |
| 独特知识提炼（动词+名词） | `ddd-knowledge-insight` / C8 | 只设计探询，不提炼 |
| 顾客分析调研设计 | `ddd-customer-survey` | C 类提示对接 D1，不重做 |
| 结论/战略建议 | 人工 | 只提取组织，结论标「需人工复核」 |

## 三、平台检测补充
- 运行时检测 connector 状态（飞书/钉钉/企微/问卷星）。
- 当前默认：检测后询问用户是否沉淀探询表到对应平台多维表格。
- 沉淀为**检查项**而非默认动作，避免未授权外发。
