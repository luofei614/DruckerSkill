# Drucker Opportunity Synthesis（德鲁克机会综合 · 三向融合升华）

> 本技能是 `ddd-` 德鲁克家族的「第 7 环·交汇升华」：消费两条已完成的平行分析流（顾客洞察 / 知识洞察）的机器可读 bundle，把德鲁克反复强调却长期未被工具化落地的 **「知识与市场双向反馈」** 变成可执行步骤；并进一步引入 **第三维「外部市场情报」**，让 AI 把对整个行业的更广认知带入机会研判，发现企业内部调研永远触不到的市场空白与能力差距。
> 形态对齐 `ddd-customer-insight` / `ddd-knowledge-insight`（能力边界 / 输出契约 / 红线 / 门禁 / human-in-the-loop）。

## 能力边界（4 问）

- **承接的重复任务**：把「顾客洞察 bundle」+「知识洞察 bundle」+「市场情报上下文(market_context)」三向交汇，推演双向反馈闭环（知识→市场 / 市场→知识）+ 外部市场融合（市场趋势×内部独特知识 / 市场要求−内部能力），套德鲁克 7 大创新源做机会研判，产出三清单 + 矩阵 + 外部印证/差距表。
- **产出**：新机会清单（含来源维度分层）+ 企业需补充的新能力清单（含市场要求差距）+ 创新源命中表 + 机会×能力矩阵 + 外部印证/差距表（HTML，打印友好）+ [内部]方法论说明（Markdown 源 + Word(.docx)）。均含来源类型、原话/出处溯源、置信度、状态。
- **不路由的近邻（exclusions）**：
  1. 不做顾客/知识探询设计（那是 `ddd-customer-survey` / `ddd-knowledge-survey`）；
  2. 不实际执行访谈 / ASR 转写 / 不做原始市场调研（市场情报由用户提供简报或 AI 检索公开信息，且须标注出处）；
  3. 不重复顾客/知识分析本身（那是 `ddd-customer-insight` / `ddd-knowledge-insight`；本技能消费其 bundle，不重算）；
  4. 不替代战略咨询 / 不替企业拍板——AI 只做「提取、交叉、升维、列假设」，决策交人；
  5. 创新源研判只产出「机会假设 + 命中源标注」，是否把「新知识创新」加进课程由人拍板；
  6. **绝不编造市场信息**：外部市场情报必须可溯源（公开报告/检索来源）；无检索能力或用户未提供时，明确标「外部情报缺失·建议补充市场简报」，不得凭空生成行业结论。
- **细节在 SKILL.md 之外**：双向反馈算法见 `references/bidirectional_playbook.md`；市场情报采集与结构见 `references/market_intelligence.md`；7 源详解见 `references/innovation_sources.md`；输出字段定义见 `references/canvas_schema.md`；理论底座见 `references/drucker_kb_precompiled.md`。

## 何时使用（When to use）

- 用户已完成「顾客洞察」+「知识洞察」两份 bundle，问「两边怎么打通」「错失了哪些市场机会」「我们要补什么能力」「用德鲁克创新源看新机会」。
- 用户明确要「结合更广阔的市场/行业趋势看机会」「把 AI 对【外部行业信息】这类市场的认知用进来」「机会综合能不能不只看企业自己」。
- **前置条件**：`ddd-customer-insight` 与 `ddd-knowledge-insight` 各自产出的 `delivery_bundle.json` 至少其一存在；两者皆缺时提示用户先跑上游。市场情报上下文(market_context) 为**可选增强**——有则三向融合，无则退回纯双向并标注「未引入外部市场情报」。

## 总流程（三向融合 · 9 步）

```
① 读取双 bundle（customer + knowledge）
→ ①.5 读取/构建 市场情报上下文（market_context，第三维·可选增强）
→ ② 知识→市场反馈（知识结论揭示错失/低估的市场机会）
→ ③ 市场→知识反馈（市场结论揭示待补的新知识/能力）
→ ④ 外部市场→机会（外部趋势 × 内部独特知识 = 市场空白机会）
→ ⑤ 市场要求→能力差距（整个市场要求 − 内部现有能力 = 结构性能力缺口）
→ ⑥ 新机会清单（聚合 ②+④，按来源维度分层）
→ ⑦ 新能力清单（聚合 ③+⑤，含市场要求差距）
→ ⑧ 创新七源研判（重点第7源 新知识 kp-i09-01）
→ ⑨ 综合矩阵 + 外部印证/差距表 + HTML 组装
```

详细算法与字段映射见 `references/bidirectional_playbook.md`。

### ① 读取双 bundle
- 主输入：`ddd-customer-insight` 的 `delivery_bundle.json`（顾客侧）+ `ddd-knowledge-insight` 的 `delivery_bundle.json`（知识侧）。二者缺一时提示补齐。
- 解析规则：
  - **顾客 JSON**：`canvas[]` 中 `col ∈ {顾客是谁, 买的是什么, 认为的价值}` 的结论 + 原话/置信度/状态；特别关注 `cell_id == "3.4"`（D1 独特价值候选，顾客侧「独特价值」种子）。
  - **知识 JSON**：`canvas[]` 三源列（跟别人比/跟自己比/问优秀顾客）的独特知识候选与知识短板（1.2）；`report[]` 第 A 节「动词+名词独特知识清单」、第 B 节「四维度诊断」薄弱项、第 C 节「五维交汇事业新机会假设卡」（其 `顾客三问` 列本就消费顾客 JSON，本技能在其上做**二次双向交汇**）。
- **路径发现（无固定路径兜底）**：若未显式给定路径，按 glob `**/delivery_bundle.json` 检索，并据 `meta.business` / `meta.title` 及 `canvas[].col` 判别顾客 vs 知识（知识 bundle 的 col 必为三源列、report 含「五维交汇」；顾客 bundle 的 col 必为顾客三问）。无法区分时询问用户。

### ①.5 读取/构建 市场情报上下文（第三维 · 可选增强）
- **输入 `market_context`**：描述企业所在「行业/品类市场」的公开情报，结构见 `references/market_intelligence.md`。两种获取方式：
  1. **用户简报**（首选，最干净）：用户粘贴行业报告 / 研报 / 市场简报，或指向 `market_context.md` / `market_context.json`。直接解析使用。
  2. **AI 检索**（增强）：若用户未提供，技能调用 WebSearch，针对「{事业/品类}  + 市场趋势 / 渠道变化 / 消费者变迁 / 竞争格局 / 人口与认知变化」做定向检索，把结果结构化沉淀为 `market_context`（每条带来源 URL/报告名 + 置信度 中/低·需核实）。
- **缺省处理**：若两者皆无（用户未提供且无检索能力），跳过 ④⑤ 中的外部部分，退回纯双向，并在产出物显著标注「未引入外部市场情报·机会可能偏窄」。
- **红线**：外部市场情报**必须可溯源**，不得编造；检索结果须保留来源链接/报告名，置信度一律中/低并标「需核实」。

### ② 知识→市场反馈（错失/低估的市场机会）
遍历知识 JSON 的「独特知识 / 五维交汇假设卡 / 四维度薄弱项」，与顾客 JSON 的「非顾客(M5) / 竞争替代(M6) / 独特价值(D1)」交叉；凡知识侧已识别价值但顾客侧非顾客组/竞争组**未覆盖**者 → 标记为 **「错失或低估的市场机会」**（措辞须用 kp-07-09 权威"错失或低估"，禁写"错过"）。来源类型标 `企业原话`。

### ③ 市场→知识反馈（待补的新知识/能力）
遍历顾客 JSON 的「未满足需求 / 非顾客原因 / 竞争短板(D1 缺口)」，反查知识 JSON 是否已有对应知识；若无 → 产出 **「企业需补充的新知识/能力」** 候选（对称知识侧 1.2 知识短板）。来源类型标 `企业原话`。

### ④ 外部市场→机会（②' · 第三维融合）
遍历 `market_context` 的「趋势 / 渠道变化 / 消费变迁 / 竞争结构 / 人口与认知变化」，与内部独特知识(K001–K005 等)交叉：
- 外部趋势/空白 × 内部独特知识 = **市场空白机会**（如：健康零食趋势 × K001 薄饼护城河 = 健康薄饼；银发/单身/县域人口 × K003 柔性制造 = 区域定制 OEM）。
- 外部渠道崛起 × 内部能力 = 渠道型机会（如：零食量贩/折扣店崛起 × K003 柔性 = 差异化 OEM）。
- 来源类型标 `市场公开信息`；置信度中/低·需核实；原话溯源改标「出处(src)」指向 market_context 条目来源。
- 若某机会同时被内部双向(②)与外部(④)印证 → 在 ⑥ 机会清单中归为「交叉验证」来源维度，置信度上调。

### ⑤ 市场要求→能力差距（③' · 第三维融合）
以 `market_context` 描述的「整个市场对研发/品牌/供应链数字化/组织能力的要求」为基准，减去内部现有能力（知识 JSON 独特知识 + ③ 已识别缺口），产出 **结构性能力缺口**：
- 例：全行业品牌化、供应链数字化是结构性差距，不限于企业个案；内部知识短板(如 K002 未机制化)在外部标准下缺口更显性。
- 来源类型标 `市场公开信息`；与 ③ 内部缺口合并进 ⑦ 新能力清单，按来源维度区分「内部缺口 / 市场要求差距」。

### ⑥ 新机会清单（聚合 ② + ④）
聚合 ② 与 ④，每条含「机会描述 / 来源维度(内部双向·外部市场空白·交叉验证) / 来源溯源(企业原话 src 或 市场出处) / 置信度 / 状态 / 初步命中创新源」。来源维度用于一眼区分"来自企业自己"还是"来自广阔市场"。

### ⑦ 新能力清单（聚合 ③ + ⑤）
聚合 ③ 与 ⑤，每条含「能力缺口 / 来源维度(内部缺口·市场要求差距) / 命中证据(企业原话 或 市场出处) / 建议知识补强方向 / 置信度」。

### ⑧ 创新七源研判（重点第7源 新知识 kp-i09-01）
对 ⑥ 每条机会，套 `references/innovation_sources.md` 的 7 源清单做归因，**重点第7源 新知识（kp-i09-01）**——当机会由「新出现的知识/技术/认知」驱动时显式命中 kp-i09-01 并 cross-link kp-07-04；外部市场情报会显著补强 人口(kp-i07-01)/认知(kp-i08-01)/产业结构(kp-i06-01) 三外部源的研判质量（不再是仅访谈里提到的抖音/无糖）。其余 6 源作可选项标注。产出「创新源命中表」，并单列「新知识创新机会假设卡」供用户决策是否把"新知识创新"加进课程。

### ⑨ 综合矩阵 + 外部印证/差距表 + HTML 组装
- `机会×能力矩阵` = 行=新机会清单、列=新能力清单，单元格=「是否需要该能力支撑该机会 / 支撑强度(高/中/低) / 备注」。用 `assets/opportunity_matrix_template.html` 渲染三清单 + 矩阵 + **外部印证/差距表** + [内部]说明。
- **外部印证/差距表**（新增）：列出「哪些内部判断被外部市场数据印证（置信度上调）/ 哪些外部机会内部完全无能力（明确差距）/ 哪些外部情报与内部结论冲突（需复核）」，让"企业自己 vs 广阔市场"的差异一目了然。
- **外部市场情报来源索引（报告末尾附录）**：引入 market_context 时，把其全部条目出处（报告名 / URL）汇总为「七、外部市场情报来源索引」置于报告末尾，保留外部信息的**来源地址**供核查；"同上"等省略写法须展开为真实出处。未引入时该表标「未引入外部市场情报·机会可能偏窄」。同一份数据写入 `delivery_bundle.json` 的 `source_index`。
- 随后用 `scripts/export_docx.py` 把 [内部]方法论说明转真实 Word。

## 数据信任分层（来源类型 · 不可省略）

所有机会/能力条目必须打 **来源类型** 标签，禁止混淆：

| 来源类型 | 含义 | 置信度基准 | 溯源要求 |
|---|---|---|---|
| `企业原话` | 来自双 bundle 的顾客/知识原话 | 高（双源一致）/ 中 | ≥1 条原话 src |
| `市场公开信息` | 来自 market_context / WebSearch 公开情报 | 中 / 低（须标"需核实"） | ≥1 条出处（URL/报告名） |
| `AI推演` | 仅本技能交叉升维所得、无直接原话/出处 | 低 | 标「AI推演·待验证」 |

- 外部市场情报**不得**伪装成企业原话；凡标 `市场公开信息` 的条目，其"来源溯源"列必须写市场出处，而非顾客/知识 cell_id。
- 无检索能力且用户未提供简报时，整份产物外部相关条目标「外部情报缺失·建议补充 market_context」，不得虚构。

## 输出契约（Output Contract）

- **机会综合画布（HTML）**：新机会清单（含来源维度）+ 新能力清单（含市场要求差距）+ 创新源命中表 + 机会×能力矩阵（打印友好、可导出 PDF）+ **外部印证/差距表** + **外部市场情报来源索引（报告末尾附录，留存来源地址）**。
- **[内部]方法论说明（Markdown 源 + Word(.docx)）**：三向融合逻辑、数据诚信边界、来源类型分层、AI 角色边界、与上下游衔接；经 `scripts/export_docx.py` 真实转换（禁止仅改后缀）。
- 客户产物纯净度同上游标准（零 `kp-` / 德鲁克 / 方法论）。

## 德鲁克红线（不可违背）

1. **双向反馈措辞**：一律用「**错失或低估**」(kp-07-09 权威引言，禁写"错过"/"漏掉")。
2. **原话/出处溯源**：每条机会/能力须 ≥1 条溯源（企业原话 src 或 市场出处）；无溯源标「证据不足·建议补访」或「外部情报缺失」。
3. **草稿不结论**：双向反馈与三向交汇一律标「草稿·假设·待验证」，绝不替企业拍板。
4. **纯净度**：HTML 交付物字符串扫描命中 `kp-` / 德鲁克 / 方法论 即返工（[内部]说明另成文档）。
5. **置信度**：沿用上游 高/中/低 + 状态枚举（已验证 / 假设·待验证 / 证据不足·建议补访）。
6. **human-in-the-loop**：含结论性表述须标「需人工复核」；外部驱动机会一律「需核实市场数据」。
7. **创新源命中必标注**：每机会须标明命中的具体源（如 kp-i09-01）——**精确 KP 编号仅写在 [内部]方法论说明(Word) 与 delivery_bundle.json 的 source_hits**；客户 HTML 用可读名（如"新知识·第7源"），不出现 `kp-` 字符串，与红线4纯净度一致。
8. **不重复上游**：只消费 bundle 做交叉，不重算顾客/知识分析。
9. **外部情报不编造**：market_context / WebSearch 结果必须可溯源；无来源不得写行业结论；缺省时显式标注「未引入外部市场情报」。

## 门禁（生产级）

- **双 bundle 校验**：各自 `build_bundle.py validate` 通过；顾客 bundle 的 col 为顾客三问、知识 bundle 的 col 为三源列（不可假设同一 enum）。
- **原话/出处溯源自检**：每条机会/能力是否 ≥1 溯源（企业原话 src 或 市场出处）？无则标「证据不足/外部情报缺失」？
- **来源类型分层自检**：是否每条机会/能力都打了 `企业原话`/`市场公开信息`/`AI推演`？外部条目是否真写了市场出处（而非伪装成企业原话）？
- **纯净度自检**：交付 HTML 字符串扫描，命中 `kp-` / 德鲁克 / 方法论 即返工。
- **Word 自检**：[内部]方法论说明须生成 `.docx`（`scripts/export_docx.py` 真实转换）。
- **措辞自检**：是否出现"错失或低估"而非"错过"？创新源是否逐条标注 KP？
- **外部情报诚信自检**：标 `市场公开信息` 的条目是否都有出处？无检索/无简报时是否显式标注「未引入外部市场情报」而非编造？
- **来源地址留存自检**：引入 market_context 时，报告末尾「七、外部市场情报来源索引」是否汇总了全部外部出处（报告名 / URL）？"同上"等省略是否已展开为真实出处？未引入时是否显式标注「未引入外部市场情报」？
- **资源边界自检**：SKILL.md 只承载路由/骨架/契约/红线；细节在 `references/` 与 `assets/`。
