# 双向反馈 + 第三维融合操作手册（Bidirectional & Market Playbook）

> 配合 `SKILL.md` 总流程。本手册定义"知识↔市场"双向反馈与"外部市场情报"第三维融合的**交叉算法**、**数据信任分层**与**字段映射**，确保 synthesis 消费的是两份 bundle 的**结论与原话** + 一份 market_context 的**公开情报**，而非重算上游、亦不编造市场。

## 0. 输入契约回顾
- 顾客 bundle（`ddd-customer-insight`）：`canvas[].col ∈ {顾客是谁, 买的是什么, 认为的价值}`；特别关注 `cell_id=="3.4"`（D1 独特价值候选）。
- 知识 bundle（`ddd-knowledge-insight`）：`canvas[].col ∈ {跟别人比, 跟自己比, 问优秀顾客}`；`report[]` 含 A（动词+名词独特知识清单）/ B（四维度诊断）/ C（五维交汇·事业新机会假设卡，首列 `顾客三问`）。
- 市场情报上下文（`market_context`，可选）：`items[]` 每条含 `dimension ∈ {趋势, 渠道变化, 消费变迁, 竞争结构, 人口与认知变化}` + `claim` + `source`（必填）+ `source_type=市场公开信息` + `confidence`。
- 三者 col / 字段 **互不相同**，解析时分别按来源区分，不可假设同一套。

## 0.5 市场情报上下文输入约定（①.5）
- 优先用用户简报（`market_context.md`/`market_context.json`）；无则本技能 WebSearch 定向采集并落盘，每条带来源 URL + 置信度中/低·需核实。
- 无简报且无检索能力 → 跳过 ④⑤ 的外部部分，退回纯双向，产出物标「未引入外部市场情报·机会可能偏窄」。

## 1. ② 知识→市场反馈（揭示"错失或低估的市场机会"）
**遍历**：知识 bundle 的 { 独特知识(A 节) ∪ 五维交汇卡(C 节) ∪ 四维度薄弱项(B 节·薄弱项Top }。
**交叉**：对每条知识结论，查顾客 bundle 的 { 非顾客(M5) ∪ 竞争替代(M6) ∪ 独特价值(D1·cell 3.4) }。
**判定规则**（命中即产出一条"错失或低估的市场机会"，来源类型 `企业原话`）：
- 知识侧已识别某独特价值/机会，但顾客侧**非顾客组**未覆盖该人群 → "错失了 {人群} 市场"。
- 知识侧识别的价值，顾客侧**竞争替代(M6)**显示被别家用更低价/更便利满足 → "低估了 {维度} 的替代威胁/错位机会"。
- 知识侧 四维度薄弱项（如"深：只在创始人脑子里"），而顾客侧 D1 显示该知识正是顾客看重的独特价值 → "错失把内部知识产品化/规模化的机会"。
**措辞锁定**：一律"错失或低估"（kp-07-09），**禁写"错过"**。

## 2. ③ 市场→知识反馈（揭示"待补的新知识/能力"）
**遍历**：顾客 bundle 的 { 未满足需求(M4/M5) ∪ 非顾客原因(M5) ∪ 竞争短板(D1 缺口) }。
**反查**：上述需求在知识 bundle 中是否有对应"独特知识/资源"可支撑？
**判定规则**（无对应知识即产出一条"企业需补充的新能力"，来源类型 `企业原话`）：
- 顾客有明确未满足需求，但知识 bundle 独特知识清单无对应项 → "需补充 {领域} 的新知识/能力"（对称知识侧 1.2 知识短板）。
- 非顾客因"不会用/看不懂"流失，而知识侧无"把复杂知识讲简单"的独特知识 → "需补强 {表达/教学} 能力"（cross-link kp-07-08 知识的表达）。
- 竞争替代显示别家某能力更强，知识侧无对应 → "需补 {能力} 以守住 {价值锚点}"。

## 3. ④ 新机会清单（聚合 ② + ②'）
每条记录字段（对齐 `canvas_schema.md`，**新增来源维度**）：
`机会描述 | 来源维度(内部双向/外部市场空白/交叉验证) | 来源溯源(企业原话src 或 市场出处) | 置信度 | 状态 | 初步命中创新源`
- 来源维度 `内部双向`：来自 ②；`外部市场空白`：来自 ②'；`交叉验证`：② 与 ②' 同时印证（置信度上调一档）。
- 状态：已验证 / 假设·待验证 / 证据不足·建议补访。
- 仅标注，不替结论。

## 4. ⑤ 新能力清单（聚合 ③ + ③'）
每条记录字段（**新增来源维度**）：
`能力缺口 | 来源维度(内部缺口/市场要求差距) | 命中证据(企业原话 或 市场出处) | 建议知识补强方向 | 置信度`

## 5. ⑥ 创新七源研判（对 ④ 每条归因）
- 对每条机会，套 `innovation_sources.md` 七源特征词匹配。
- **重点**：当机会由"新出现的知识/技术/认知"驱动 → 命中 **kp-i09-01（新知识·第7源）**，并 cross-link kp-07-04。
- 其余 6 源作可选标注；**外部市场情报会显著增强 人口(kp-i07-01)/认知(kp-i08-01)/产业结构(kp-i06-01) 三外部源**——不再是仅访谈里提到的抖音/无糖，而是整个市场的人口结构、认知迁移、渠道重构。
- 产出"创新源命中表"：机会 | 命中源(KP) | 说明。
- 单列"新知识创新机会假设卡"：机会描述 | 驱动的新知识 | 与现有知识资产距离 | 可行性/难度 | 是否建议加进课程（人拍板）。

## 6. ⑦ 机会×能力矩阵
- 行 = ④新机会清单；列 = ⑤新能力清单（含市场要求差距项）。
- 单元格 = { 是否需要该能力支撑该机会(是/否) | 支撑强度(高/中/低) | 备注 }。
- 渲染见 `assets/opportunity_matrix_template.html`。

## 7. 数据诚信边界（human-in-the-loop）
- 所有机会/能力必须可回溯到双 bundle 的**原话**（src）或 market_context 的**出处**（source）。synthesis 不做新访谈、不编造原话、不编造市场。
- 双向反馈与三向交汇一律"草稿·假设·待验证"，最终决策交企业。
- 若某机会在双 bundle 均无原话支撑、且无 market_context 出处 → 标"证据不足·建议补访"或"外部情报缺失"，不进主清单。

## 8. ②' 外部市场→机会（第三维融合 · 新增）
**遍历**：`market_context.items[]` 的 { 趋势 / 渠道变化 / 消费变迁 / 竞争结构 / 人口与认知变化 }。
**交叉**：对每条市场情报，查知识 bundle 的 { 独特知识(A 节 K001–K005) ∪ 五维交汇卡(C 节) }。
**判定规则**（命中即产出一条"市场空白机会"，来源类型 `市场公开信息`，置信度中/低·需核实）：
- **趋势 × 独特知识** = 市场空白机会：如 "健康零食/无糖趋势" × K001 薄饼护城河 → 健康薄饼线；"银发/单身/县域人口变化" × K003 柔性制造 → 区域定制 OEM。
- **渠道变化 × 内部能力** = 渠道型机会：如 "零食量贩/折扣店崛起" × K003 柔性 + K005 灵活合作 → 差异化 OEM；"内容种草成为终端推力" × K002 关系型履约 → 动销赋能包。
- **消费变迁 × 内部产品知识** = 用途扩展机会：如 "解馋/充饥/情绪价值场景迁移" × K001 产品优势 → 场景化新品。
**溯源要求**：每条须回溯 market_context 的 `source`（URL/报告名），**不得**写成顾客/知识 cell_id；无 source 不写。

## 9. ③' 市场要求→能力差距（第三维融合 · 新增）
**基准**：以 `market_context` 描述的"整个市场对研发/品牌/供应链数字化/组织能力的要求"为标尺。
**计算**：市场要求 − 内部现有能力（知识 JSON 独特知识 + ③ 已识别缺口）= **结构性能力缺口**。
**判定规则**（来源类型 `市场公开信息`）：
- 全行业级差距：如 "全行业品牌化/供应链数字化" 是结构性要求，内部明显不足 → 市场要求差距（不限于企业个案）。
- 内部知识短板在外部标准下更显性：如 K002 关系型履约"未机制化"，在外部"组织能力标准化"要求下缺口放大。
- 与 ③ 内部缺口合并进 ⑤ 新能力清单，来源维度区分「内部缺口 / 市场要求差距」。

## 10. 数据信任分层（来源类型 · 不可省略）
所有机会/能力条目必须打 **来源类型**，禁止混淆：

| 来源类型 | 含义 | 置信度基准 | 溯源要求 |
|---|---|---|---|
| `企业原话` | 来自双 bundle 的顾客/知识原话 | 高（双源一致）/ 中 | ≥1 条原话 src |
| `市场公开信息` | 来自 market_context / WebSearch 公开情报 | 中 / 低（须标"需核实"） | ≥1 条出处（URL/报告名） |
| `AI推演` | 仅本技能交叉升维所得、无直接原话/出处 | 低 | 标「AI推演·待验证」 |

- 外部市场情报**不得**伪装成企业原话；凡标 `市场公开信息` 的条目，其"来源溯源"列必须写市场出处。
- 无检索能力且用户未提供简报时，外部相关条目标「外部情报缺失·建议补充 market_context」，不得虚构。

## 11. 外部印证 / 差距表（新增产出）
列出"企业自己 vs 广阔市场"的差异，让 ⑨ 综合矩阵之外多一张对照表：
- **印证**：内部判断（②/③）被外部市场数据(market_context) 印证 → 该机会置信度上调一档，来源维度改「交叉验证」。
- **差距**：外部机会/要求内部完全无能力支撑 → 明确标注"能力缺口·市场级"。
- **冲突**：外部情报与内部结论矛盾（如内部认为某渠道重要、外部数据显示该渠道已衰退）→ 标「需复核·数据冲突」，交企业判断。
- 该表同时是回流 `ddd-knowledge-survey` 的信号：提示企业"补采市场级知识"以缩小视野差。

## 12. 外部市场情报来源索引（来源地址留存 · 报告末尾附录）
满足"外部信息的来源地址在报告最后保留"的要求——把本报告消费的全部 `market_context` 条目出处集中列在末尾，便于核查与复核，也堵住"市场信息无处溯源"的隐患。
- **来源**：直接复用 `market_context.items[]`（id / dimension / claim / source / confidence），逐条转成索引行。
- **必填字段**：`source` = 公开报告名 / 检索 URL；出现"同上"等省略写法时**必须展开为前一条真实出处**，不得把"同上"原样进索引。
- **渲染位置**：HTML 模板「七、外部市场情报来源索引」置于「六、新知识卡」之后、footer 之前。
- **缺省**：未引入 market_context 时，该表仅一行「未引入外部市场情报·机会可能偏窄」，不得留空或虚构。
- **机器可读**：同一份数据并行写入 `delivery_bundle.json` 的 `source_index` 数组，供下游/人工复核。
- 与红线 9「外部情报不编造」一致：索引里的每条来源地址都须真实可查。
