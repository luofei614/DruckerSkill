# 平台检测与问卷沉淀指引

在步骤 ⑦，检测用户是否具备把问卷模板沉淀到"多维表格/AI表格/问卷平台"的能力，有则询问并执行，没有则仅交付本地 Markdown。

## A. 能力检测（看已连接的 connector）

检查运行环境中 `<connector-status>` 里以下项是否为 `connected`：

| 目标平台 | connector 关键字 | 沉淀方式 |
|---|---|---|
| 飞书多维表格 | `feishu` | 用飞书 MCP 建多维表格：一行=一道题，列含 模块/题号/题干/题型/是否必答/分支条件/对应KP |
| 钉钉AI表格 | `dingtalk` | 用钉钉 MCP 建表；字段同上 |
| 企业微信AI表格 | `wecom` / `wecom` 智能表格 | 用企微 MCP 建表；字段同上 |
| 腾讯问卷 | `tencent-survey` | 用腾讯问卷 MCP 建问卷（题型直接映射） |
| 金数据 | `jinshuju` | 用金数据 MCP 建表单 |
| 问卷星 | （无官方 MCP connector） | 生成"问卷星导入格式"文本/表格，指引用户手动导入 |

> 注：连接状态会变化。检测当下状态，不要假设。若目标 connector 未连接，提示用户："检测到 X 平台未连接，可在连接器管理里连接后重试，或我先交付本地模板/导入格式。"

## B. 沉淀执行流程

1. 列出**当前可用**的平台（connected 的），询问用户选哪个（或全都要）。
2. 用户选定后：
   - **多维表格/AI表格类**（飞书/钉钉/企微/金数据）：调用对应 MCP 创建一张"问卷设计表"，把 7 模块题库逐行写入，列结构统一为：
     `模块 | 题号 | 题干 | 题型(开放/单选/多选/排序/NPS) | 是否必答 | 分支条件 | 对应KP`
   - **问卷平台**（腾讯问卷）：调用 MCP 直接建问卷，按题型映射（开放题→填空，因素排序→排序题，NPS→量表）。
   - **问卷星**：输出一份"可粘贴导入"的题目清单（每题一行，标题型），并给出手动导入步骤。
3. 回传平台链接/表格 ID 给用户。
4. **红线保留**：无论落到哪个平台，防引导校验规则不变；开放题不得被平台强行改成封闭选项。

## C. 无可用平台时

仅交付本地：`questionnaire_template.md`（问卷）+ 导入格式段落，并说明"当前无已连接的表格/问卷平台，已生成本地模板与可导入清单，连接后可一键沉淀"。

## D. 钉钉沉淀实战要点（实战沉淀）

1. **两种表分开建**：「问卷设计表」（一行=一题，字段：模块/题号/题干/题型/是否必答/分支条件/对应KP）供内部管理；**收集答卷必须另建「答卷回收表」**（一个字段=一题、一行=一份答卷），再用 `dws aitable form create --base-id --table-id --name --description` 创建 FormDesigner 表单视图，才能发给被调研者填写。
2. **字段类型映射**：开放题→text；路由/筛选题→singleSelect（选项即分支）；排序题在表单中用 text 让填写者手写顺序（AI 表格无排序题型）；表单描述里写分支作答指引（如「合作中答1-15题」）。
3. **建表限制**：table create 单次最多带 15 个字段，超出部分用 field create 追加；批量 create_fields 易报 TIMEOUT_ERROR，改为逐字段+重试（≤3次）更可靠，完成后必须校验字段总数与重复。
4. **超时防重**：table create 网络超时后服务端可能已建成，重试前先 `table list` 查重，避免产生「xx 1」重复表。
5. **分享链接**：视图 URL 格式 `https://docs.dingtalk.com/i/nodes/{baseId}?iframeQuery=sheetId%3D{tableId}%26viewId%3D{viewId}`；对外公开收集需用户在钉钉客户端打开表单视图手动开启「分享收集」。
